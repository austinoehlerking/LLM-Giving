# Versioned research packet contract and readable results

New trusted snapshots carry workflow.packet_contract_version=research-packet-v2. The version is read from the server-loaded immutable snapshot after the task/revision/context signature check. Packet fields cannot select it. Snapshots without that marker retain research-packet-v1: no new usefulness requirement, the original 10-byte source-excerpt and 20-byte acceptance-quote minimums, and the original 200,000-byte packet budget. Existing issued archives and stored scientific bodies/disclosures are not rewritten.

The current packet budget is 4,194,304 UTF-8 bytes of canonical JSON. Authorized transport has its own raw stream/owner bounds; offering a large transport does not waive field, evidence, rights, file or completeness limits. Existing supporting-file limits remain 12 files, 30,000 bytes per file and 80,000 bytes total. Direct and resumable entry must pass the same final locked business checks. No submitted code is executed by the site.

## Shared interfaces

- wf_packet_contract(task, nullable snapshot) returns version, deterministic digest, structural schema, UTF-8 byte/list limits, eligible current result references and repair guidance. A null snapshot means the current contract for developer/authoring use; it grants no submission authority.
- wf_packet_errors(packet, task, nullable snapshot) returns the common structural and relationship diagnostics together. Each diagnostic has path, code, IDs, observed value/size, constraint and repair guidance. Scientific support, consent, current eligibility and specialized evidence remain final server checks.
- wf_packet_template_extension(task) supplies unsigned authored usefulness fields. The signed example builder must add these only for newly issued v2 snapshots; nonce/HMAC fields are preserved.
- wf_packet_throw(errors, trustedVersion) throws WfPacketError, an HttpError with status422, errors and schemaVersion. Existing route catches merge wf_packet_exception_details(error) into JSON responses. No catch needs to parse/revalidate a multi-megabyte packet.

Observed free text is redacted to its type/UTF-8-byte size; public claim/source/result IDs are bounded and credential-like IDs redacted. Do not serialize the original packet into public errors, logs or exports. Diagnostics inspect at most each declared list maximum plus50 entries and emit an explicit scan_bound if more remain. At most1,000 detailed errors are emitted, followed by diagnostics_limited. Preserve the complete original private packet, repair its stated bounds, and recheck; this is not permission to discard evidence or claim a complete scan of oversized invalid input.

## Common evidence limits and relationships

The schema and final normalization share limits:30 searches,40 sources,20 central claims,12 relation edges per claim,20 basis results per claim,300 source-review and acceptance checks. The browser consumes the server-issued schema and never writes the authored packet. If an entered packet references another preserved snapshot, the browser defers to the server’s captured-contract validation rather than applying the currently displayed schema to old signed work. Targeted repairs go to the same authoring worker, retaining signed identifiers, scientific meaning, contrary evidence and uncertainty. A Check records no result and does not advance a task.

A basis result must be current, public, accepted research or synthesis work in the same study. It need not be a declared task dependency. Planning, quarantined, foreign, stale and invalidated results are excluded. Original-source links remain required; a prior result or receipt does not prove a scientific claim.

There is one edge for each claim/source/relation triple. The edge retains its primary locator/excerpt/explanation. Its optional passages list retains up to12 additional distinct locator/excerpt pairs, rather than duplicate edges. For v2, an inspected excerpt may be1–1,500 UTF-8 bytes: use the shortest sufficient exact passage and never pad it. Unavailable sources cannot supply quotations or support. The site does not fetch sources; actual source access and quotation fidelity require independent scrutiny. Acceptance evidence_quote still must exactly occur in the referenced retained result, even when a short sufficient quote is allowed.

## Useful work and reading order

Every new v2 packet authors usefulness version1 with question_helped, intended_user, finding, why_it_matters, increment, established, uncertain, reusable_output and next_use (10–2,000 UTF-8 bytes each). The prompt mandates readable, finding-first output, then why it matters, useful work added, established facts and uncertainty, reusable output and next use. Methods/evidence follow; material inventory and provenance/audit are expandable. The expanded inventory uses friendly category/material labels while preserving exact technical references in separate audit disclosures. Retained filenames and the contributor’s rights statement remain intact; inert download actions have at least44-pixel touch targets and retain the existing accepted/current-result authorization check. The finding must also occur verbatim in the full authored body, preventing a detached reader-facing scientific claim. The renderer displays these authored values and never creates a scientific interpretation, changes units/conditions, rounds historical numbers, or converts signed aggregate motion into a sinking-only endpoint.

A useful increment can organize evidence, synthesize disagreements, replicate a check or clarify uncertainty. Null and unresolved findings remain eligible. A breakthrough, positive conclusion, invented saved-hour/impact metric or computation merely to fill a schema is not required. Field presence is an authoring requirement, not automatic proof of usefulness.

For v2 independent review, evidence.usefulness_reviews identifies every eligible retained output with task_id, result_id, verdict (useful, needs_correction, unverifiable), reason, exact retained output_quote and next_use. Reviewers assess the increment against the actual requested deliverable. Missing or unverifiable useful work requires needs_correction and a usefulness-standard correction through the existing dependent-task invalidation path. Historical outputs without an authored reading aid require a whole-result usefulness assessment, not an invented summary or retroactive rewrite.

## Prospective formatting-only policy

Only server-captured consent with influence_policy_version=formatting-only-v1 enables human_interaction/human_disclosure level=formatting_only, category=formatting and truthful details. wf_influence preserves the raw self-report and delegates to wf_formatting_influence. This permits presentation-only headings, layout or line wrapping while preserving scientific claims, methods, evidence choices, conclusions and uncertainty. It carries no editorial-assistance badge and does not establish an untouched conversation.

Editorial, methodology, evidence, conclusion guidance and uncertainty still require influence review. Unknown categories are rejected; a substantive category cannot disappear under level=none. An untrusted packet cannot choose the policy version. Existing influenced or quarantined records remain influenced/quarantined until an explicit administrator decision; nothing auto-resubmits, approves or applies them. A session with no independently collected contributor declaration remains explicitly not_collected.

## Developer verification

Use node tests/research-schema.mjs for pure PHP/browser parity and policy fixtures. tests/research-schema-integration.php covers trusted-version compatibility, all observed repair failures together, exact short quotes, a valid packet above275k bytes, useful null findings, independent usefulness corrections, read-only Check and quarantine. node tools/qa.mjs schema is the focused repository browser route for readable accepted/quarantined/legacy/formatting receipts and unchanged Check/Submit. Set QA_INSPECT_FIRST=schema to pause after the three required initial viewport sets for image inspection before any action. Browser artifacts belong under storage/qa/schema and are not committed. Independent batch review/QA and explicit deployment authorization remain separate.

For a narrow retry after a read-only browser-helper failure, QA_SCHEMA_PHASE=submission runs only packet Check/Submit. Its report must name separately retained, still-valid inspected visual evidence; do not label combined partial invocations as a clean full run. QA_SCHEMA_PHASE=tables reruns only the affected table/file/reflow views, retaining the independently inspected first-viewports and successful submission phase separately. Separate contributor disclosure must be selected before server Check: when the packet references a different preserved context, client preflight correctly defers to the server and the normal authorization/disclosure checks run first.
