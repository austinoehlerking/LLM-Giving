# Visual research artifacts

Research packets can now include native charts, diagrams, step-based animations and interactive scenario pages. Artifacts are generated by the volunteer's AI as structured data and rendered by local PHP/SVG plus a small local JavaScript controller. No runtime AI, external chart service, remote font, uploaded script or production Node process is used.

## Contributor and reader workflow

1. Copy a fresh task handoff. The optional visual format is included across planning, research, synthesis and review.
2. Ask the AI to include an appropriate visual deliverable in the unchanged task packet. Planning can specify the visual and its data/evidence needs. The AI puts typed data in evidence.datasets and specifications in evidence.artifacts.
3. Use Check packet. Existing source/claim checks and the visual validator run together; a failed packet receives the platform repair prompt. The volunteer does not manually edit scientific data or identifiers.
4. After a terminal result is accepted, its Visual research artifacts section exposes Explore artifact. The research brief and workflow also have a current-artifact catalogue.
5. Readers can change supplied scenarios, step through or explicitly play animation states, inspect text equivalents, follow evidence links, read methods/assumptions/limits and export JSON, CSV or SVG.

Controls are ahead of the visual on narrow screens. Charts and diagrams keep readable SVG text in a keyboard-focusable horizontal scroll region; full data tables and textual explanations provide alternatives. Animations do not autoplay, stop at the final state, respect pause, stop when the page becomes hidden and retain manual steps under reduced motion. Without JavaScript the initial native figure, complete data and all state descriptions remain available.

## Data and artifact format

The complete trusted format is in templates/artifacts.txt and is included in every task prompt and repair handoff. Existing evidence version 1 packets remain compatible when the new optional lists are absent. Verified reviews must supply visual audits when current research/synthesis results contain artifacts.

- evidence.datasets: up to 8 datasets, each with id, title, provenance, source_ids, method, limitations, uncertainty, columns and rows. Columns are typed number/text with explicit units for numbers. Rows contain literal finite numbers, text or null; null is missing and is never filled with zero. Limits: 2–8 columns and 1–100 rows per dataset.
- evidence.artifacts: up to 6 artifacts with id, title, kind, purpose, summary, provenance, claim_ids, source_ids, dataset_ids, assumptions, limitations, method, control_label, panels and states. Provenance is observed, derived, illustrative or simulated. Every linked claim source, including contrary/context evidence, and every backing dataset source must remain in the artifact source registry.
- panels: static charts/diagrams use one matching panel; animations and interactive pages allow 1–3 chart/diagram panels. Charts support bar, line and scatter, one x column and 1–3 numeric y series with matching units. Diagram nodes have bounded positions and plain-text labels/details; edges reference existing distinct nodes.
- states: animation/interactive artifacts have 2–12 described states. Filters select exact typed data rows; highlights select known diagram nodes. No arbitrary formulas, model execution or interpolation is performed in the viewer. The renderer limits total plotted marks across states to 3,000.
- evidence.artifact_reviews: server-issued task_id, result_id, artifact_id plus verdict and reason. Verdicts are supported, needs_correction or unverifiable.

Observed/derived datasets require inspected provenance. Illustrative/simulated data cannot be relabeled observed/derived, and any visual containing simulated data stays simulated. Each visual must link at least one central claim in the same packet and state its assumptions, method and limitations. Source access and scientific support remain contributor/reviewer declarations. Structural checks cannot establish scientific truth.

Line charts leave gaps for missing observations. Bars include a zero baseline. Axes and series retain units; underlying tables, JSON and CSV preserve supplied values. Visuals with multiple units on one y axis, missing data in every selected state, overlapping diagram nodes, invalid references, unknown fields or oversized scenes fail packet checks.

## Routes and exports

The public artifact page is:

/research/{slug}/results/{result-id}/artifacts/{artifact-id}

Its read-only exports are:

- /spec.json — reproducible llm-giving-visual-v1 artifact, backing datasets, selected claims and source records. Only allowlisted public result identity is returned; actor hashes, packet hashes, nonces, disclosures and signatures are excluded.
- /data/{dataset-id}.csv — only datasets actually linked to that artifact. Formula-like text is prefixed for spreadsheet safety; numeric negative values remain numeric.
- /panels/{panel-id}.svg?state={state-id} — a locally generated static figure for the selected supplied state. SVG contains provenance, claim/data/source identity and accessible descriptions. It is served as an attachment with a sandboxed content policy.

The site hosts bounded native scenario pages. This implementation does not host arbitrary submitted HTML/JavaScript, arbitrary chart libraries, custom executable simulations or uploaded animation files. Those formats are rejected instead of executed. The existing separately moderated attachment workflow is unchanged.

## Visibility and corrections

Every page/export checks public parent visibility, result admission/moderation, task visibility, the current planning round, current accepted result pointer and snapshot revocation. Quarantined/rejected packets cannot expose visual pages or exports. A corrected/superseded result loses its live preview/download routes. Its original structured specification stays in historical context; the result page labels its preview unavailable. The current catalogue excludes it.

Independent review must audit every current research/synthesis artifact alongside every claim. Reviewers assess source/data fidelity, units, axis/legend labels, missing/omitted data, provenance labels, assumptions, uncertainty and whether the visual overstates the evidence. A failing visual audit requires needs_correction. The server creates an artifact-standard correction identifying the artifact, reopens the responsible task and all transitive dependents, and preserves unrelated accepted work. Admin approval revalidates quarantined packets through the same path. Ordinary claim and criterion corrections continue to work.

## Verification commands

- node tools/dev.mjs setup
- node tools/check.mjs — includes artifact PHP integration, playback/reduced-motion logic and HTTP/export checks alongside existing suites.
- node tools/qa.mjs artifacts — repo-owned Edge route on 127.0.0.1:8095; owns its PHP server, creates only disposable [Artifact QA] fixtures and checks first-viewport actions before interacting.
- node tools/qa.mjs — existing mandatory general browser route.

Only after the primary browser route fails, the in-app browser can use an artifact fixture created with tests/artifact-state.php. tools/artifact-browser-fallback.mjs provides read-only snapshots for 200% text, script-free rendering and a clearly simulated reduced-motion preference. It writes only under storage/qa/artifacts on D:, does not submit results and stops only its own server. The regular native-browser tests also contain real reduced-motion emulation and JavaScript-disabled contexts.

See research-artifacts-qa.md for executed checks and limitations. No deployment or production access is included.
