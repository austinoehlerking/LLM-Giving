# Guided AI request setup

The submission form offers **Copy AI prompt to assist setup** alongside Submit for approval. The button copies a locally composed interview prompt and reveals **Paste setup prompt**. The user takes the prompt to their own AI, answers one question at a time, pastes its final JSON output, and selects **Fill request fields**. All request fields remain editable and use the existing review/submission flow. Filling never submits or approves a request.

## Prompt and form contract

The prompt includes the selected project type and current public draft, exact enabled category names, the configured model/reasoning policy, field limits and a complete versioned JSON template. It guides scope, intended use, success criteria, existing work, references, constraints, uncertainty, questions and tags. Tool projects add users, bounded requirements, input/output specifications, reference/boundary/invalid-input tests, assumptions and maintenance status. Calculation execution is an explicit choice. Any AI can assist with setup; configuration restrictions apply to later contributions and must permit mandatory planning.

Do not claim generated requests are scientifically correct or perfect. The guide asks follow-up questions, prohibits invented evidence/permissions and leaves unknown optional facts empty. It explains open licensing and independent review. Private email, attribution/profile links, attachments and terms are completed on the website; their existing values are excluded from copied draft context and preserved during import. Consent is cleared after replacing draft content so the human can review it again.

`public/assets/request-setup.js` builds the exact prompt and validates the complete `llm-giving-request-setup-v1` object before changing any field. It checks the public field allowlist, JSON shape/types, UTF-8 limits, project/category choices, tool requirements, actual booleans and compatible AI settings. Unknown/protected fields or incomplete/malformed output leave the entire current draft untouched. A single JSON code fence is tolerated. Text is assigned through native field values, never HTML. Model/project change events keep existing conditional controls and required fields in sync. No runtime AI calls, network requests, dependency, persistent browser storage, server endpoint or database migration was added for the helper.

The paste buffer and manual prompt textareas have no form names and never enter submitted FormData. Their height is bounded so the fill action remains reachable. Clipboard failure opens/selects the exact prompt for manual copying; a readable copy is available after every copy action. Without JavaScript, a native manual interview guide is available below the core request fields and ordinary server-rendered submission continues to work. Server-side validation, terms, initial moderation and all workflow permissions are unchanged.
