# AI browser return verification

The default path is volunteer authorization, complete handoff, AI browser work/check/repair/submit, and a recorded receipt. Manual return is labeled Manually submitted and remains a discouraged fallback. Submission method and influence are separate declarations.

## Acceptance criteria

- A volunteer can authorize one ready assignment without an account, accepting the displayed legal version, separate software consent where applicable, and an independent public human-input declaration through authorization.
- A separate anonymous browser can use the private return link without inventing consent or replacing the volunteer declaration. The original actor is preserved for independent-review checks. Public archives/context exclude return credentials and actor capabilities.
- Check packet does not submit or consume the grant. Recoverable errors can be repaired in the same conversation; stale tasks, requirements or terms require reassessment and fresh authorization. Accepted/quarantined results consume the grant once, and recovery retrieves the existing receipt.
- Method labels appear on receipts, public records, audit and admin surfaces. Historical missing methods stay not recorded. Actual scientific influence or uncertainty retains quarantine/moderation; unchanged copying, operational permission and platform formatting repair do not falsely imply influence.
- Supplementary original/follow-up/progress/review contributions retain their own provenance and moderation rules, preserve their selected kind/target and do not complete planned tasks. Guided request drafting remains a separate human-reviewed import.
- Required primary actions remain visible, unobscured and at least 44 CSS pixels high at 1366x768, 390x844 and 375x667. Enlarged text reflows without horizontal clipping. Native forms also support the authorized path without JavaScript.
