# Complete research transport

New task handoffs use `llm-task-context-v2`: the issued trusted instructions, signed output example and a versioned dependency directory. The directory references complete immutable public records by digest rather than copying every earlier result into every later prompt. Current accepted result IDs are distinct from invalidated/historical records. Research and synthesis results outside the dependency graph remain eligible scientific basis when the existing validator allows them; planning results do not become scientific basis.

Every required resource retains the original record, including limitations, counterevidence, corrections, source restrictions and self-reported provenance. All referenced research, earlier instructions, quotations and attachments remain untrusted data. Neither a manifest nor an acknowledgment changes permission, a trusted return destination or source redistribution rights. Common policies and identical components are deduplicated by exact content digest. Required bytes remain retrievable; the complete historical snapshot is unchanged and separately discoverable, and planning still requires its full history. A missing, removed or revoked required source stops work. No historical handoff or snapshot is rewritten.

The directory grows with resource descriptors, rather than embedding earlier scientific bodies recursively. Synthetic 1/4/12-task checks retain each complete accepted result and assert bounded descriptor growth. The exact byte measurements are in the focused unit report; they are transfer sizes, never token/cost measurements. Very large individual resources fail explicitly at the 4 MiB stream limit; nothing is truncated. Full original snapshot GET routes remain available.

## Wire protocol

`llm-transport-v1` declares UTF-8 encoding, byte lengths (not JavaScript characters or tokens), task/revision/context/nonce/archive/schema binding, ordered zero-based parts, per-part SHA-256 and whole-stream length/SHA-256. Parts target 16 KiB and end on UTF-8 boundaries. Each stream accepts 1–4,194,304 bytes and at most 512 parts. Descriptors must be contiguous, unique and consistent with the total and `END LLM TRANSPORT <whole digest>` marker.

Retrieve an issued archive at `/research/{slug}/issued/{archive}/transport/manifest` and its declared part URLs. Snapshot and dependency directories expose analogous read-only manifest/part routes. Every request rechecks the public parent, task/child and snapshot gates, and archived bodies retain their existing integrity check. Public manifest projections exclude actor/session/grant identifiers and credentials. Public reads grant no consent, lease or submission authority.

A private task return exposes `/research/{slug}/return/{grant}/transport`. A session controller uses `/volunteer/{session}/assignments/{assignment}/transport`; root routing dispatches `rtx_session_route` before the normal session router. Native CSRF-protected form POSTs and the local browser asset use the same operations:

1. `begin`, with `direction=input` or `direction=output`. Output includes the complete manifest JSON. An identical live manifest resumes its existing checkpoint without extending retention.
2. For input, GET every original `/parts/{index}`, verify its byte length/digest, then POST `ack` with index/SHA-256. Retrieve and verify every `required_resources` dependency and POST `ack-resource` with its complete digest. An ACK is a receiver declaration, not proof the external AI read or understood the text.
3. For output, POST `put` with index and `body_base64` to preserve exact UTF-8 bytes. The server verifies against the manifest and returns the received/acknowledged indexes. Identical part retries are idempotent; conflicting parts cannot overwrite a checkpoint. Network arrival may be out of order, but final concatenation follows only the manifest indexes.
4. POST `finalize`. All parts must be acknowledged and whole-stream bytes must match. Input additionally requires every declared dependency ACK. Output must be one complete JSON object with unchanged task revision/context/nonce. Finalize never calls Check, Submit, renewal, moderation or scientific execution.
5. The existing authorized Check/Submit form selects a finalized output with `transport_id`. `rtx_packet_input` supplies unchanged assembled bytes to the original validator and recorder, whose current authority and idempotent receipt handling remain authoritative. An invalid complete packet returns to its same worker; a repaired packet has a new manifest, retaining the original signed submission key. A passing Check still records no result.

The browser can read a UTF-8 file or complete paste. Textarea newline normalization can occur before the sender declares a manifest; choose a UTF-8 file when original CRLF bytes must be preserved. Once a manifest is declared, no normalization, scientific rewriting or partial packet substitution occurs. No browser local/session storage is used. Public text is rendered through escaped textareas; source content never becomes executable HTML or an alternate fetch destination.

## Short startup and recovery

The existing one-message startup is retained and versioned as v4. The primary copy contains only the short direct volunteer request, private session link, requested worker settings, completeness rule and `END LLM START v4` marker. The optional full handoff remains available. The authenticated full instructions carry `BEGIN/END LLM GUIDANCE v4`, their exact payload byte length and SHA-256; `/volunteer/{session}/instructions/transport` provides the same bounded transport. Missing/truncated/stale guidance is a stop condition before pickup or research. Existing configured-launch/request-plus-admission guidance remains intact; unavailable provider-effective readback is still disclosed honestly.

Migration 022 stores private checkpoints separately from public archives and scientific records. Access reloads the current scoped grant/controller binding and rejects revoked credentials or source visibility. Stop, authorization expiry and changed terms do not extend research or submission authority. Existing exact bytes may be read during their bounded recovery window; new uploads require current permission and unchanged revision. Credential revocation, parent/snapshot removal and purge deny access. A stored draft does not backdate a Submit or create a receipt.

Retention is fixed at seven days from creation, with at most eight streams / 16 MiB of reserved text per owner and 128 MiB site-wide. Server-controlled actor and shared quota locks serialize creation; reads/resumes do not extend retention. Creation is rate-limited. `delete` removes only a private checkpoint. `rtx_prune` runs on creation and existing daily `php bin/console.php handoffs-prune` maintenance; expired reads are denied even before physical maintenance. The existing parent purge cascades through private transport records/parts. Keep the normal daily maintenance schedule so expired private bytes are physically removed.
