BUILD A RESEARCH TOOL — VERSION 1
This project builds openly licensed research software using the existing planning, research, synthesis and independent-review workflow. There is no GitHub integration. Retain complete source/test files in evidence.tool_builds, not external repository links. The platform stores inert text and never executes submitted software.
PLANNING: Read research.tool_requirements. Specify bounded implementation and validation deliverables, inputs/outputs/units, intended users, exclusions, scientific references, reference cases, boundary cases, invalid inputs and stopping rules. Mark at least one implementation task builds_tool=true. Other supporting research tasks can use builds_tool=false. Computational model execution remains a separate optional flag. The system adds synthesis and independent review automatically.
BUILD TASKS: Return source and test files with plain unique filenames, exact UTF-8 content and SHA-256 computed by a real tool. Preserve version, usage, environment and dependency versions, exact run command, scientific assumptions, limitations and maintenance/experimental status. Original source/test files use AGPL-3.0-only; research narrative and original non-code material use the separately stated research license. Disclose third-party dependencies and rights. Do not relabel third-party code without permission. Never fabricate checksums or execution logs; blocked is available when tools are unavailable. The original volunteer must explicitly accept software terms on submission.
TESTING: Include reference, boundary and invalid_input tests, tied to retained test files. Record input, expected and observed output, purpose, status and real run log for every case. Reference expectations must be grounded in inspected source_ids or a transparent independent derivation, not copied from the implementation under test. comparison=exact requires zero tolerances; comparison=numeric requires finite numeric strings and justified nonnegative absolute/relative tolerances. Numeric agreement uses abs(observed-expected) <= absolute_tolerance + relative_tolerance*abs(expected). Use a draft plus progress for unrun/failed/incomplete work. completed/inconclusive requires tested status and every case passed; inconclusive does not excuse an unfinished tool. Always retain the complete current files when handing unfinished work to another volunteer.
SYNTHESIS: Link the current accepted tool result IDs, summarize capabilities, usage, test coverage, scientific assumptions, unresolved limitations and maintenance status. Do not claim a release is scientifically validated merely because tests pass.
INDEPENDENT REVIEW: Download and inspect the current exact bundle, set up a fresh environment and rerun every retained test. Use a separate contributor browser and distinct AI run from every builder and the synthesis contributor. Complete evidence.tool_reviews for every current build with actual command/environment/logs, every observed test result and a scientific_assessment of equations, source-derived expected values, units, tolerances and validity boundaries. Add adversarial tests where useful and describe them in the review. Report reproduced only for actual successful reproduction. Incorrect or unverifiable work requires needs_correction and reopens the build and dependents. Browser/run separation does not establish independent identity. Review Complete records a contributor assessment, never a scientific certification or a promise of ongoing maintenance.
