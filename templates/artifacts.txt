TRUSTED VISUAL RESEARCH ARTIFACT FORMAT — version 1
Visual aids are optional. Add them when they make the research easier to inspect or understand; never invent observations to fill a chart. Planning may specify a visual deliverable and its evidence/data needs. Research and synthesis may supply evidence.datasets and evidence.artifacts. Reviews must audit every current research/synthesis artifact through the artifact_reviews template. Existing source/claim rules still apply.
The platform renders native charts, diagrams, animations and interactive scenario pages from data. Return structured specifications inside the existing evidence object. Do not return HTML, CSS, SVG, JavaScript, external assets, executable formulas or URLs to embed. Nothing is uploaded separately. Use empty datasets/artifacts lists when no visual is useful. Each artifact is versioned with its immutable result and is withdrawn from current preview/download routes when that result is corrected or removed.
DATASET FORMAT (evidence.datasets, up to 8):
{id, title, provenance, source_ids, method, limitations, uncertainty, columns, rows}
provenance: observed | derived | illustrative | simulated. Observed/derived data require inspected source_ids. Explain extraction or derivation exactly in method; state uncertainties and access limits. Illustrative/simulated values must be labeled honestly; assumptions are not measurements.
columns: 2–8 {key, label, type, unit} records. key uses lowercase letters/digits/underscores/hyphens and starts with a letter; type is number or text. Numeric units are mandatory (use dimensionless where appropriate). rows: 1–100 arrays in exactly the same column order. Numbers are finite JSON numbers between -1e12 and 1e12; text is plain text. null means missing, never zero. Do not put formulas in cells. IDs must be unique within each record list.
ARTIFACT FORMAT (evidence.artifacts, up to 6):
{id, title, kind, purpose, summary, provenance, claim_ids, source_ids, dataset_ids, assumptions, limitations, method, control_label, panels, states}
kind: chart | diagram | animation | interactive. title is 5–100 characters. purpose explains the research question this visual addresses; summary is its accessible text equivalent. assumptions, limitations and method must each explain the actual model/representation and how to reproduce it. claim_ids reference central claims in THIS packet; source_ids reference THIS packet's source registry. dataset_ids reference backing datasets in THIS packet. Include every linked claim source (including contrary/context evidence) and all dataset source_ids in the artifact source_ids. A visual containing simulated data must be simulated; illustrative data cannot be presented as observed/derived. Diagram relationships are conceptual unless the evidence establishes them.
CHART PANEL: {id, title, type:"chart", dataset_id, chart_type, x, y}. chart_type is bar, line or scatter. x is a column key; y is a list of 1–3 distinct numeric column keys sharing the same units. Line/scatter x must be numeric; bars accept text or numbers. Bar axes include zero; line/scatter axes show their numeric range. Lines connect supplied observations without creating new measurements. Every visual state must have real plottable values. Do not imply statistical uncertainty that the data does not contain; explain it in uncertainty and use explicit lower/upper columns as separate labeled series if useful.
DIAGRAM PANEL: {id, title, type:"diagram", nodes, edges}. nodes: 1–16 {id, label, detail, x, y}; positions are percentages with x=12..88 and y=14..86. Space nodes so their boxes do not overlap; labels are 1–60 characters and detail explains the full node in text. edges: up to 30 {from, to, label}, referencing two distinct node IDs. No remote images or markup.
A static chart/diagram has exactly one matching panel, states:[] and control_label:"". An animation or interactive page has 1–3 panels, 2–12 states and a meaningful control_label. Animations are explicit step-based scenes (no autoplay); interactive pages let readers select supplied scenarios. No arbitrary computation or interpolation is performed by the viewer.
STATE FORMAT: {id, label, explanation, filters, highlights}. Each state explains what changes and what does not. filters: [{panel_id, column, value}] selects exact typed backing-data rows for a chart. Filters for a panel are combined with AND. highlights: [{panel_id, node_ids}] highlights diagram nodes. Use empty filters/highlights where unnecessary. Every declared dataset must be used by a chart panel. Rendering is bounded to 3,000 plotted marks across the artifact's states. Keep states and panels purposeful.
VISUAL REVIEW FORMAT (evidence.artifact_reviews): retain each supplied task_id, result_id and artifact_id; set verdict to supported, needs_correction or unverifiable and give reason. Independently assess numerical fidelity, units, axis/legend labels, omitted/missing data, source/claim links, provenance labels, assumptions, uncertainty, limits and whether the explanation overstates the evidence. Verified requires every current artifact audit. needs_correction/unverifiable verdicts require outcome needs_correction; the server generates an artifact-standard correction and reopens that task and its dependents. Never call a visual verified just because it renders. Original JSON, CSV data, SVG figures, text descriptions, pause/step controls, reduced-motion behavior and source links are available to readers.
